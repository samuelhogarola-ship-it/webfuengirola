# WF-Studio: arquitectura SEO local y multilingüe

Fecha: 2026-09-05

## 1. Objetivo

Convertir la web pública en un activo de captación fuerte en español, inglés,
alemán y finés, usando Fuengirola como núcleo inicial de relevancia local sin
limitar la futura expansión geográfica de la marca WF-Studio.

La estrategia debe:

- aumentar la visibilidad para búsquedas comerciales relacionadas con diseño
  web y Fuengirola;
- captar solicitudes de presupuesto, mensajes y auditorías, no solo tráfico;
- ofrecer la misma capacidad comercial en los cuatro idiomas;
- especializar la oferta por tipo de negocio;
- mantener tres modalidades comunes y comprensibles en todas las webs;
- aprovechar casos reales y experiencia propia como principal señal de
  confianza;
- evitar páginas repetitivas creadas únicamente para cubrir variaciones de una
  palabra clave.

## 2. Arquitectura de marca

La marca principal será **WF-Studio**. **Web Fuengirola** seguirá funcionando
como denominación local y activo SEO durante una transición progresiva.

Fórmula inicial recomendada:

> WF-Studio · Web Fuengirola

Fórmula posterior, cuando WF-Studio tenga reconocimiento propio:

> WF-Studio — diseño web y SEO en Fuengirola

No se contempla por ahora un cambio brusco de dominio. El dominio y las URLs
que ya acumulan señales orgánicas se conservan. La identidad visual, textos de
marca y datos estructurados deben introducir WF-Studio de manera coherente sin
ocultar la relación con Web Fuengirola.

Los datos estructurados de organización deben usar WF-Studio como nombre y Web
Fuengirola como nombre alternativo. Los datos de negocio local y el perfil de
Google deben conservar información real y consistente; no se declararán sedes
que no existan.

## 3. Modelo comercial

### 3.1 Productos principales

El producto comercial no es una combinación técnica genérica. Cada producto es
una web adaptada a un tipo de negocio o necesidad concreta, por ejemplo:

- web para clínicas;
- web para fisioterapeutas;
- web para entrenadores personales;
- web para gimnasios;
- web para restaurantes;
- web para negocios locales;
- web multidioma.

Cada landing debe hablar de los problemas, recorridos de conversión,
funcionalidades, ejemplos y objeciones propios de ese sector.

### 3.2 Modalidades comunes

Todos los productos especializados ofrecen las mismas tres modalidades y
precios base ya definidos:

| Modalidad | Precio base | Alcance actual |
| --- | ---: | --- |
| Web Lite | 200 € + IVA | Una página enfocada a conversión, contacto y SEO base |
| Web Express | 350 € + IVA | Hasta cinco páginas, servicios, preguntas y opción de blog |
| Web Profesional | 600 € + IVA | Hasta diez páginas, captación avanzada, analítica y mayor recorrido |

Los nombres, precios y límites deben proceder de una única fuente de datos para
que no diverjan entre sectores o idiomas.

La modalidad no cambia según el sector. Lo que cambia es la explicación de
cómo se utiliza su alcance. Por ejemplo, una Web Express para restaurante puede
dedicar sus páginas a carta, reservas, ubicación y contacto; una Web Express
para clínica puede dedicarlas a tratamientos, profesionales, citas y contacto.

### 3.3 Extras y proyectos a medida

Los siguientes elementos se presentan como extras compatibles o ampliaciones,
no como productos principales independientes:

- blog;
- migración;
- optimización;
- formularios adicionales o avanzados;
- idiomas adicionales;
- mantenimiento;
- hosting y correo;
- integraciones.

Las aplicaciones web, paneles internos y automatizaciones pueden seguir siendo
servicios propios cuando el alcance exceda una web comercial. No deben
confundirse con las modalidades Lite, Express o Profesional.

### 4.2 Landings sectoriales iniciales

Las primeras landings españolas serán:

- `/web-para-clinicas-fuengirola/`;
- `/web-para-fisioterapeutas-fuengirola/`;
- `/web-para-entrenadores-personales-fuengirola/`;
- `/web-para-gimnasios-fuengirola/`;
- `/web-para-restaurantes-fuengirola/`;
- `/web-para-negocios-locales-fuengirola/`;
- `/web-multidioma-fuengirola/`.

Cada una tendrá una URL equivalente con slug natural y localizado en inglés,
alemán y finés. No se indexará la versión de un idioma hasta que tenga copy
completo, enlaces, metadata, modalidad, precios y llamada a la acción.

### 4.3 Límite de expansión

No se crearán automáticamente combinaciones de sector, localidad y servicio.
Una nueva landing necesitará:

1. una intención de búsqueda diferente;
2. contenido y propuesta realmente específicos;
3. capacidad de prestar el servicio;
4. enlazado interno y una llamada a la acción propios;
5. preferiblemente un caso, ejemplo o demostración relevante.

Mijas, Benalmádena y otras localidades se abordarán después de observar datos
de Search Console y conversiones en Fuengirola. La expansión no debe fingir
oficinas o presencia física inexistentes.

## 5. Uso de Fuengirola

Fuengirola será una entidad local transversal, no una palabra repetida sin
contexto. En las páginas cuya intención sea local aparecerá en:

- URL cuando resulte natural;
- title y H1;
- introducción y propuesta comercial;
- cobertura real del servicio;
- casos, ejemplos y testimonios locales;
- preguntas frecuentes;
- breadcrumbs y enlazado interno;
- textos alternativos cuando la imagen represente realmente un negocio o lugar
  de Fuengirola;
- datos estructurados y perfil de Google cuando corresponda.

Los contenidos también pueden aportar contexto mediante Los Boliches,
Torreblanca, Carvajal y Costa del Sol, siempre que exista una relación real con
el servicio o el caso descrito.

No se fijará una densidad artificial ni se insertará Fuengirola en todos los
párrafos. La relevancia procederá de profundidad temática, relaciones internas,
experiencia local, datos coherentes y menciones externas.

## 6. Plantilla de una landing especializada

Cada landing sectorial tendrá como mínimo:

1. Hero con sector, resultado esperado y Fuengirola.
2. Problemas habituales del sector.
3. Funcionalidades y beneficios relevantes.
4. Caso real, ejemplo o demostración relacionada.
5. Comparación Web Lite, Web Express y Web Profesional.
6. Extras compatibles.
7. Proceso de trabajo.
8. Preguntas frecuentes propias del sector y del mercado local.
9. Cobertura de Fuengirola y entorno real.
10. CTA a presupuesto, WhatsApp y auditoría.
11. Enlaces a SEO local, casos y artículos relacionados.

Las modalidades compartirán datos base, pero la explicación de cada una se
adaptará al sector. El contenido no debe prometer funcionalidades que no entren
en el alcance o precio mostrado.

## 7. Paridad multilingüe

La paridad exige que los cuatro idiomas compartan:

- catálogo de productos especializados;
- modalidades, precios y alcance;
- páginas de servicio;
- casos relevantes;
- página de precios;
- auditoría y contacto;
- navegación y llamadas a la acción;
- información legal necesaria;
- medición de conversiones.

El copy se localizará, no se traducirá palabra por palabra. El alemán y el
finés hablarán especialmente a residentes y propietarios de negocios que
operan en la Costa del Sol. El inglés cubrirá tanto empresarios internacionales
como negocios locales que necesitan captar clientela extranjera.

Cada grupo equivalente usará:

- canonical propio;
- `hreflang` recíproco para español, inglés, alemán y finés;
- español como `x-default` durante esta fase;
- selector de idioma que conserve la página equivalente;
- slugs comprensibles en el idioma de destino;
- presencia en el sitemap solo cuando la página esté lista para indexarse.

Una comprobación automática debe fallar si una página publicada pierde una
alternativa, un canonical, una referencia recíproca o la correspondencia de
precios.

## 8. Navegación y enlazado interno

La navegación principal de cada idioma contendrá:

- Inicio;
- Webs especializadas;
- SEO local;
- Aplicaciones y automatización;
- Casos;
- Precios;
- Blog;
- Contacto.

Cada landing especializada debe enlazar a:

- sus tres modalidades;
- un caso real o ejemplo relacionado;
- el servicio de SEO local;
- uno o más artículos especializados;
- la auditoría;
- presupuesto y WhatsApp.

Los artículos enlazarán a una landing comercial principal según su intención,
en lugar de repartir la conversión entre varias páginas equivalentes. Los casos
enlazarán al producto sectorial y al servicio utilizado.

## 9. Tratamiento de las páginas actuales de productos

Las páginas de `/productos/` no se borrarán de forma automática. Antes de
actuar se revisarán tráfico, impresiones, enlaces internos y enlaces externos.

Para cada URL se escogerá una de estas acciones:

- reconvertirla en galería o contenido de apoyo si conserva ejemplos útiles;
- redirigirla a la landing sectorial o de servicio más próxima si describe una
  combinación que ya no se vende como producto;
- conservarla temporalmente con una función informativa claramente distinta.

Las páginas que mezclan Lite o Express con blog, migración, optimización o
formularios no deben seguir presentándose como productos principales. Esos
elementos pasan a la sección de extras dentro de la oferta correspondiente.

## 10. Conversión y medición

Los eventos mínimos serán:

- clic en WhatsApp;
- clic en teléfono;
- clic en correo;
- inicio y envío de formulario;
- solicitud de auditoría;
- uso y resultado de la calculadora;
- paso de blog a landing comercial;
- selección de modalidad;
- cambio de idioma;
- sector e idioma de la conversión.

La auditoría gratuita pedirá URL, sector, localidad, problema principal y dato
de contacto. Debe incluir consentimiento, estados de error comprensibles,
protección antispam y confirmación de recepción. No prometerá un informe
automático si el análisis requiere revisión humana.

El éxito se medirá por leads cualificados y solicitudes de presupuesto, además
de impresiones, clics y posiciones. Search Console y Umami decidirán qué sector
o idioma se amplía después de la primera fase.

## 11. Contenido editorial

Los nuevos artículos priorizarán decisiones próximas a la contratación:

- qué debe incluir un presupuesto web;
- pago único frente a cuota mensual;
- landing o web completa;
- WordPress o web a medida;
- rediseñar o crear una web nueva;
- captar clientes extranjeros con una web multilingüe;
- SEO multilingüe para negocios de la Costa del Sol;
- necesidades digitales de clínicas, restaurantes, gimnasios y entrenadores;
- cuándo conviene un panel de gestión o una automatización.

Cada contenido incluirá conocimiento propio, ejemplos o decisiones prácticas.
No se crearán artículos genéricos únicamente para aumentar el número de URLs.

## 12. Fases de entrega

### Fase 1: sistema común

- Crear la fuente única para productos, modalidades, precios e idiomas.
- Crear la plantilla de landings especializadas.
- Añadir validaciones de paridad, canonical, `hreflang` y sitemap.
- Definir la presentación dual WF-Studio · Web Fuengirola.

### Fase 2: núcleo comercial multilingüe

- Crear `/en/`, `/de/` y `/fi/`.
- Publicar diseño web Fuengirola en los cuatro idiomas.
- Publicar precios, auditoría y contacto equivalentes.
- Asegurar navegación y medición equivalentes.

### Fase 3: sectores con evidencia propia

- Clínicas y fisioterapia.
- Entrenadores personales y gimnasios.
- Restaurantes.
- Negocios locales y web multidioma.
- Mejorar y conectar casos relacionados.

### Fase 4: consolidación

- Revisar y reconducir las URLs antiguas de productos.
- Publicar contenido editorial de apoyo.
- Analizar Search Console y Umami.
- Priorizar nuevas localidades o sectores según demanda y conversión.

## 13. Criterios de publicación

Una landing no se indexará hasta cumplir todos estos criterios:

- contenido específico del sector y localizado al idioma;
- modalidades, alcance y precios correctos;
- caso, ejemplo o demostración relevante;
- CTA funcional y medido;
- metadata, canonical y `hreflang` válidos;
- datos estructurados coherentes con el contenido visible;
- enlaces entrantes y salientes pertinentes;
- inclusión correcta en sitemap;
- navegación móvil y formularios verificados;
- ausencia de afirmaciones locales o resultados no demostrables.

## 14. Fuera de alcance

Esta especificación no autoriza todavía:

- cambiar el dominio;
- abandonar la denominación Web Fuengirola;
- crear páginas masivas por cada combinación de sector y localidad;
- alterar los precios aprobados;
- inventar sedes, reseñas, casos o métricas;
- modificar el repositorio separado `wf-studio-panel`.

La implementación de la web pública se realizará en este repositorio. Cualquier
cambio futuro del panel WF-Studio seguirá perteneciendo al repositorio separado
`wf-studio-panel`.
